# Changelog

## 0.1.0 (прежние обозначения «2.x» и «3.0» в истории — внутренние этапы разработки)

### Этап 2 · Windows и Linux
- Исправлено до этапа: надёжная запись `library.json` (fsync, копия `.bak`, восстановление при повреждении), позиция просмотра сохраняется при паузе и закрытии, `remove()` ждёт остановки задачи, закрытие не зависает на зависшей модели.
- Пути вынесены в `paths.cjs`: данные Linux `~/.config/anime-lingo-desktop` (без миграции), Windows `%APPDATA%\anime-lingo-desktop`; компоненты Linux `~/.local/share/anime-lingo`, Windows `%LOCALAPPDATA%\AnimeLingo`.
- Отмена задачи останавливает всё дерево процессов (POSIX — группа процессов, Windows — `taskkill /T /F`).
- Защита улучшения: Linux — systemd + bubblewrap, как раньше; Windows — упрощённый watchdog (не изоляция), честно подписан в интерфейсе.
- ffmpeg/ffprobe: поиск системных, скачивание закреплённых с проверкой SHA-256; жёсткие `/usr/bin/...` убраны.
- Диагностика GPU на Windows (WMI + реестр + nvidia-smi) без нагрузки на видеокарту.
- Произношение на Windows через System.Speech.
- Загрузчик компонентов: докачка, пауза, SHA-256, проверка места; манифест закреплённых версий (`desktop/manifest.json`, `npm run pin:manifest`).
- Сборки: Windows NSIS + portable, Linux AppImage + linux-unpacked; GitHub Actions (ubuntu + windows).

### Этап 3 · модели внутри программы
- Перевод Hy-MT2: встроенный llama-server (llama.cpp b11375, SHA-256 в манифесте) вместо LM Studio; запуск на 127.0.0.1, случайный порт, ключ из файла; выгрузка = завершение процесса; перезапуск и повтор при падении или зависании; лестница слоёв при нехватке VRAM.
- Выбор квантизации Q4_K_M / Q6_K / Q8_0, импорт ранее скачанного файла LM Studio (SHA-256, жёсткая ссылка).
- Окружение распознавания ведёт сама программа: uv, Python 3.12, PyTorch (cpu, cu126, cu130, xpu, rocm7.2 на Linux), qwen-asr; существующий qwen-env подхватывается.
- Загрузка весов Qwen из программы с проверкой SHA-256.
- Раздел «Модели»: устройства по задачам (авто или вручную), состояние и загрузка компонентов с паузой, удаление, выгрузка, папка моделей.
- Перед распознаванием на CPU показывается оценка времени.
- Удалены: LM Studio, tools/setup-local-ai.sh, tools/download-qwen-models.py.

### Этап 4 · видеокарты
- gpu.cjs: определение карт и доступных бэкендов отдельно для распознавания, перевода и видео; автоматический или ручной выбор, явный недоступный выбор — понятная ошибка.
- GPU-режим улучшения видео — отдельный, явно включаемый, с предупреждением: аппаратное кодирование (NVENC, AMF, VAAPI, QSV; выбор только после настоящей короткой проверки) и Real-ESRGAN (ncnn-vulkan) короткими отрезками с watchdog, лимитом времени и автоматическим откатом на CPU. По умолчанию остаётся безопасный CPU; для Intel Xe на Linux нужно отдельное подтверждение.

### Этап 5 · интерфейс и исправления
- Мастер первого запуска: видеокарты → что скачать (с размерами и свободным местом) → загрузка → проверка переводчика только с согласия.
- «Скопировать отчёт» в сообщениях об ошибках (система, версии, состояние компонентов; без личных путей и содержимого библиотеки).
- Раздел «Модели»: статус, устройство, прогресс, пауза, удаление, выгрузка, папка моделей.
- Перетаскивание папок; понятные сообщения о неподдерживаемых файлах; регистр путей на Windows; безопасные имена экспорта и атомарная запись экспорта; кэш совместимого видео привязан к исходному файлу.
- Ширина окна: минимум 900 DIP, проверено без горизонтальной прокрутки на 910 px.

### Интерфейс: упрощение и английский язык
- Английский язык интерфейса (Настройки → «Язык интерфейса»: как в системе / Русский / English); словарь ≈950 фраз, тест полноты по всему коду.
- Настройки: основное видно сразу, остальное в «Дополнительно». «Модели» — по вкладкам. Улучшение видео: понятные названия режимов («Безопасный режим» вместо «Бережный CPU»), лишнее свёрнуто.
